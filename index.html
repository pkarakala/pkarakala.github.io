ML Systems Accelerator Lab

🔧 UC Santa Barbara — Full Accelerator Stack GitHub

Built the full ML accelerator software stack from scratch — from PyTorch model capture to compiled kernels to cycle-accurate hardware simulation. A miniature version of what TVM, Triton, and real accelerator SDKs do at scale.

Three-Layer Stack

  • TensorDescent — Captures PyTorch models via torch.fx, propagates tensor shapes, fuses Linear+ReLU into single kernels, eliminates dead code, and plans memory for buffer reuse on on-chip SRAM. NumPy backend validates at 0.0 difference vs PyTorch.
  • KernelForge — Takes fused ops, applies loop tiling (32×32 blocks) to keep data in fast shared memory, and emits CUDA-style kernels. Inspired by how Triton approaches GPU programming.
  • AccelSim — Cycle-accurate simulation of a 5-instruction stream (LOAD/MATMUL/RELU/STORE/ADD), tracks memory traffic, measures compute vs memory utilization, and identifies bottlenecks. A 2-layer MLP comes out compute-bound at 77.8% — the signal that tells a compiler where to optimize.

Together: compile the graph → optimize the kernels → simulate the hardware → feed insights back to readjust optimization budgets.

Continuous Quantum Error Correction with ML Decoders

📍 UC Santa Barbara 👥 Co-authored with Clark Enge GitHub

Built a complete 4-phase pipeline for continuous Quantum Error Correction — from static syndromes to adaptive decoding under hardware drift. Demonstrated that ML decoders outperform Bayesian methods under realistic noise, and that online learning enables self-calibrating QEC without recalibration.

Four Phases of Increasing Realism

  • Phase 1: Static syndromes with GRU achieving 96% vs 86% threshold baseline
  • Phase 2: Time-dependent Hamiltonian dynamics — coherent drive, calibration drift, measurement backaction
  • Phase 3: Non-ideal effects — colored noise (AR(1)), post-flip transients, random-walk drift
  • Phase 4: Adaptive GRU with online learning maintains 82% accuracy as hardware parameters drift, vs 70% for Bayesian filter
